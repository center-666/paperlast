# **第一篇论文 SSCD v2：结果审核与下一阶段判断**

我核对了 GitHub [`32d2718`](https://github.com/center-666/paperlast/commit/32d27189a220ce28893bb68ac9b97cf85abeee8c?utm_source=chatgpt.com) 中的 `V2_RESULTS.md`、参数锁定文件、选参代码、实验注册和独立测试结果。

**这一轮是有价值的进展，但也暴露了当前 SSCD 算法的核心矛盾：固定负耦合水印已经表现出比较稳定的工程收益，而自动选参器却因为过于严格的逐场景认证规则，最终选择了 iid。**

这不代表负耦合无效，也不能据此宣布自动设计成功。

## **一、最值得保留的实验成果**

两个冻结动力学模型、每模型6个压力场景、每场景512条独立测试路径，得到：

| 指标              | 不稳定模型        | 稳定模型         |
| --------------- | ------------ | ------------ |
| iid 全网 MSE      | 0.061517     | 0.064659     |
| 负耦合全网 MSE       | **0.061356** | **0.064091** |
| 相对 MSE 改善       | **0.262%**   | **0.879%**   |
| 受影响5节点 MSE 改善   | **2.41%**    | **5.76%**    |
| Eligible 检测统计改善 | +0.190个百分点   | +3.606个百分点   |

这批结果使我们对论文的判断比此前更加明确：

- 水印的收益不仅存在于理论 KL 或无门控风险矩阵中，也能传递到最终共 \\(G\\) 状态估计。
- 改善在受攻击节点附近更明显，全网平均结果受到大量健康节点的稀释。
- 负耦合在全部12个固定压力场景的 MSE 点估计都优于 iid，正耦合则呈现相反趋势。

但这些仍是**锁定 iid 后对固定候选的描述性检验**，不能将负耦合追溯宣布为本轮算法选出的最优水印。

## **二、为什么自动选参最终失败？**

我从 `locked_selection.json` 中找到了确切原因。

当前选参规则要求每一个登记场景都证明非 iid 水印更好：

\\[ \max\_{s\in\mathcal S} \operatorname{UCB}\_{s} \left( \frac{J_s(\theta)-J_s(0)}{J_s(0)} \right)<0. \\]

边界负耦合的12个场景点估计均为负，但两个场景没有通过同时上置信界：

| 不稳定模型压力场景 | 观察到的相对 MSE 变化 | 同时95%上界   |
| --------- | ------------- | --------- |
| −45°，起点50 | −0.00585%     | +0.03120% |
| −45°，起点65 | −0.00635%     | +0.00696% |

这里尤其值得关注：**最困难场景中的实际收益极其微弱，只有约万分之零点几的相对变化。**

所以当前问题不完全是256条开发路径太少，而是这些场景对水印耦合本身不够敏感。

按现有第一种场景的标准误粗略外推，如果效应大小保持不变，为达到同等逐场景同时认证门槛，可能需要约一万条独立路径。这只是样本量量级估算，不是正式功效保证。

我不建议为了让负耦合通过选参规则，就直接堆上万条轨迹。即使证明了一个只有0.006%左右的相对收益，对论文的实际安全估计价值仍然有限。

**因此，本轮结论应该是：固定水印有正面证据，但 SSCD 的当前自动选参目标和认证方式仍需要重新审视。**

## **三、我发现两个需要在正式论文中纠正的评价口径**

### **1. 7.42%的健康误报不一定意味着校准程序失效**

当前阈值使用512条健康路径中第488个顺序统计量。对连续、独立同分布的健康路径，随机阈值在校准集与未来路径的联合分布下，确实具有约4.873%的边际误报率。

但固定某一次校准阈值后，实际误报概率本身是随机的。

在理想交换性假设下，512条新健康路径中至少38条报警，可以用 Beta-Binomial 预测分布计算，概率约为 **4.39%**。

因此，稳定模型的38/512值得进一步检查，但还不足以认定程序错误。建议保留原结果，在不同独立校准集上专门检验条件误报率的波动。

### **2. 当前 Eligible TPR 不是通常意义的路径检测概率**

我检查了 `run_final_evaluation.py`，现有指标实际计算的是：

\\[ \mathrm{TPR}\_{\mathrm{eligible}} = \frac{\text{eligible窗口内报警的链路—时刻数}} {\text{eligible窗口内全部链路—时刻数}}. \\]

这更接近**报警决策占比**，而不是通常的：

\\[ P(\text{攻击期间至少报警一次}\mid\text{存在攻击}). \\]

两者都可以报告，但不能混用。

另外，当前首次 eligible 报警延迟从攻击开始后的第7拍才允许计入，因此表中的7.2拍不能直接解释为实际系统平均用了7.2拍发现攻击。前7拍的报警被该评价口径排除了。

建议论文同时保留真实首警时刻、完全受攻窗口内报警占比和报警持续率，明确各自的定义。

## **四、接下来应当改进的是水印优化目标，而不是继续增加水印结构**

经过这一轮结果，我更倾向于把第一篇论文的新方法定义为：

**面向状态估计损伤的时序耦合水印设计。**

我们已经发现：负耦合的主要工程价值可能来自改变检测门控，而不是直接降低攻击扰动幅值。

但目前的优化器仍然只看整个时域的平均 MSE，没有显式体现一个重要事实：

> 在不同时间、不同邻居链路上，错误接纳一次攻击报文，对最终状态估计的伤害可能相差很大。

这恰好提供了下一步理论深化的切入点。

### **4.1 建立门控决策的状态损伤敏感度**

对于时刻 \\(k\\) 的可疑链路 \\(e\\)，考虑两种接收决策：接受或拒绝该报文。

在固定其他门控决策、相同物理数据的条件下，两种共 \\(G\\) 更新产生状态差：

\\[ d\_{k+1}^{(e)} = \hat x\_{k+1}^{\mathrm{accept}} - \hat x\_{k+1}^{\mathrm{reject}}. \\]

当后续门控保持相同时，它的传播由共 \\(G\\) 状态矩阵决定：

\\[ d_t^{(e)} = F\_{\sigma\_{t-1}}\cdots F\_{\sigma\_{k+1}}d\_{k+1}^{(e)}. \\]

于是，两种决策在第 \\(t\\) 拍造成的平方状态误差差异可以精确写成：

\\[ \boxed{ \Delta L_t^{(e)} = 2(e_t^{\mathrm{reject}})^\top d_t^{(e)} + \\|d_t^{(e)}\\|^2. } \\]

这一公式的意义在于：**我们可以把一次门控决定与它造成的后续物理状态损失直接联系起来。**

这里的真实状态误差只能用于离线评价或建立条件期望模型，不能作为在线选参器的输入，否则会产生 oracle 信息泄漏。实际算法仍需使用合法历史、模型预测和可计算的条件风险近似。

### **4.2 从普通检测信息变成任务相关检测信息**

以前，我们主要优化：

\\[ \max\_\zeta\min\_{\xi}D_G(\zeta,\xi). \\]

但 KL 是检测可分辨性的代理；即使它增加，也不一定意味着估计风险按比例改善。

现在可以考虑新的研究目标：

\\[ \boxed{ \min\_{\zeta\in\mathcal Z} \mathbb E\\!\left[J\_{\mathrm{final}}(\zeta)\right] } \\]

满足相邻互信息预算、健康误报约束和健康 MSE 约束，并在预先定义的场景集合中限制最坏性能退化。

与此同时，利用上述单次门控的反事实损伤敏感度，建立一个可计算的辅助目标，判断水印提高的是不是**对状态估计最重要的那些报文的识别能力**。

这才有可能把文章中的理论贡献从：

“改变水印时序相关性能够改善检测统计”

推进到：

“根据网络状态传播和门控决策损伤，选择能够改善最终安全估计的水印统计结构”。

需要强调，这仍是下一步待证明的算法方案，而不是现有论文已经完成的定理。

## **五、我建议重新安排接下来的研究工作**

| 优先级 | 研究任务                       | 成功标准                    |
| --- | -------------------------- | ----------------------- |
| P0  | 固化 `32d2718`，完成首警与健康误报口径审计 | 不再存在评价定义混用              |
| P1  | 建立门控决策的状态损伤敏感度及条件风险表达      | 能解释为什么负耦合在某些时刻有效        |
| P2  | 利用共同随机数与合法条件矩降低选参方差        | 不依赖盲目扩大路径数来获得微小显著性      |
| P3  | 重新设计有工程意义的期望风险—最坏退化约束      | 允许明确比较 iid、固定负耦合和任务相关选参 |
| P4  | 小规模未知攻击支持集及非 oracle 基线验证   | 证明水印在无法预先删去真实攻击链路时有价值   |

其中，P3 的优化目标不能根据本次终验结果直接改写并在同一测试集上宣布成功。新的目标、性能容忍度和信息预算都需要事先固定，再使用完全独立的数据检验。

此外，我建议先用一个可审计的小候选链路集合验证未知支持集机制，而不是立刻扩展到全网596条有向通信链路。这样更容易区分检测器、多重检验和共 \\(G\\) 增益切换各自的影响。

## **六、论文是否已经接近投稿？**

目前仍不建议直接投稿，但我认为已经有三项比较完整的研究资产：

1. **水印设计理论**：保持单拍 Gaussian 边缘，通过有符号时间耦合改变检测与污染传播统计。
2. **最终共&#x20;**\\(G\\)**&#x20;风险分析**：包含固定增益风险矩阵、数据相关门控的精确偏差递推及路径风险界。
3. **可复现工程结果**：50节点共 \\(G\\)、原六边攻击、独立校准、门控归因、锁定与独立测试，固定负耦合已经多次获得正面结果。

但审稿人仍可能提出一个合理的问题：

**既然固定负耦合已经有效，为什么还需要一个最终选择 iid 的复杂 SSCD 优化算法？**

目前我们还没有足够强的回答。

所以我的研究决定是：**保留固定负耦合作为已经获得支持的方法基线，暂不把 SSCD 自动选参作为论文的已完成核心创新。下一步优先证明“状态损伤敏感的水印设计”比普通检测导向设计具有额外价值。**

这样才能延续第一篇论文原本的研究目标——设计一种特殊水印，使它不只是帮助检测隐蔽攻击，而是真正改善分布式安全状态估计。
